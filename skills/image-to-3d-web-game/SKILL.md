# 从参考图制作 3D 网页游戏

目标是交付可运行、可游玩、可验证的网页作品，同时让参考图的视觉意图贯穿场景与玩法。根据用户要求决定是漫游、驾驶还是其他游戏，不把本案例的赛车规则强加给新项目。

## 开始前

1. 查看参考图及现有项目，区分图中**确实可见**的元素、对画面外空间的合理补全，以及后来新增的玩法地标。不要把程序生成画面标成原始参考图。
2. 记录用户已定的技术栈、目标设备、风格、交互、交付位置和必须保留的旧版本。缺少关键选择时先用最小可运行原型探索，再就真正影响方向的选择提问。
3. 若已有项目，先运行并截取基线，记录实际启动、控制、报错和画质。修改原版前确认用户是否要求独立新版；要求保留时在新目录实施。

## 工作路线

- **视觉拆解与空间草图**：提取透视、地形坡度、建筑尺度、光照、色彩与记忆点；为画面外区域设计可解释的道路和目的地。先完成一个能从多个视角成立的核心街口，再扩展地图。截图对比参考图，标明哪些是忠实借鉴、哪些是创作补全。
- **可探索场景**：让道路、地形高度、可通行边界和路口共用一份空间数据，避免视觉路面与碰撞/导航互相矛盾。先走通主路与支路，再添建筑、植被和小道具。近景集中精度，重复静态物体优先实例化或合批，远景做适度简化。
- **交互与玩法**：先做可控制的角色或车辆、镜头和安全返回，再接挑战规则。每个模式要有清楚的起点、目标、失败/完成状态和退出路径；计时、检查点、收集与存档保持独立职责。只加入用户要求的玩法。
- **环境与界面**：不同时间/天气共享场景几何，切换时检查灯光和资源不会累积。界面只显示当前模式需要的信息；暂停、失焦、切换设置和恢复时冻结或恢复相应状态，并清除残留输入。
- **验证与交付**：逻辑测试覆盖路网、碰撞、规则、进度等真正易错的行为；浏览器实测覆盖启动、操控、模式闭环、窗口变化和资源失败。用真实渲染截图检查比例、遮挡、穿插、灯光、植物轮廓与可读性；记录浏览器、设备、分辨率及实际性能，不把单元测试或自动截图成功当成视觉验收。交付启动说明、素材来源、实机截图、测试结果和已知限制。

## 关键判断

- 参考图通常只有一个机位。优先保持空间气质和可辨认的视觉线索，不为逐像素相似破坏可行走性或可驾驶性。
- 用本地静态服务运行需要加载资源的网页项目；不要以 `file://` 打开成功作为验收。运行时依赖和素材许可须清楚，避免无说明的远端资源。
- 先让完整体验闭环，再扩大地图和素材规模。渲染性能不足时优先定位植被、阴影、动态灯和重复几何的开销，并重新测量。
- 外部发布、上传或修改线上资源只在用户授权的范围内执行；本地完成不等于已发布。

若任务是复现或扩展“夏日坡道 / 夏日疾走”，或需要本 Skill 的来源案例，读取 [项目案例与验收要点](references/summer-racer-case.md)。该案例的车型、模式、地图规模与性能数值是实例，不是新项目的默认需求。
